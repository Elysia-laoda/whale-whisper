# 插件直调链路 · 实测与结论

> 记录 ZorvAI 宿主（v1.1.10）上「点挂件 → 提醒进入 AI 上下文」这条链路的逐段验证、结论与限制。
> 验证产物：`com.zorv.plugin.whale` v1.13.0（本目录 `plugin-whale/`，MIT，同为自研）。

## 一、结论

**链路是通的，每一段都有实测证据。唯一的限制是时序**：一轮的所有模型请求都在注入之前构建完成，
因此注入只能被「下一轮」读到——这也解释了为什么自动唤醒总是发生在轮末。

```
点击 → APK 写公共区 → 插件直调注入 → buf(+1) → toLlmMessages(有) → normalize(有) → 发出
```

## 二、逐段证据

| 段 | 手段 | 实测 | 结论 |
|---|---|---|---|
| 采集 | 悬浮窗 APK 写 `/sdcard/qshare/whale/pending.json` | 8 次点击 → 4 条被搬运（其余为去重命中） | 采集正常 |
| 注入 | 反射 `injectExternalReminder()` 或写 `liveBuffers[convId]` | `前=866 后=867`（+1），末条 `user/【外部事件提醒…` | 确实写进本轮容器 |
| 组装 | 反射调 `store.toLlmMessages(null,0,0)` | `buf报文=是` | 组装保留 |
| 归一化 | 反射构造 `QuroLlmClient` 调 `normalizeToolCallMessages()` | `归一化后=是(866→854)`，两次采样（size 889 / 892）均为「是」 | 发请求前仍在 |
| 序列化 | 静态读 `messageToJson` + `sanitizeForLlm` | 只处理非法代理项与控制字符，中文标记不受影响 | 不会被删改 |
| 模型 | 注入文案附带回执口令 `WHALE-ACK-xxxxxx`，插件扫 assistant 输出 | 未出现回执 | **本轮未读到** |

## 三、为什么本轮读不到（源码）

1. **两份 store**：`QuroChatViewModel.send()` 为每一轮建 turn-local 工作副本，
   `val buf = QuroConversationStore().apply { initialMessages.forEach { add(it) } }`、
   `liveBuffers[convId] = buf`、`QuroAssistant(..., buf)`（`QuroChatViewModel.kt:928-931`）。
   `injectExternalReminder()` 写的是**共享 store**，本轮 assistant 读的是 `buf` —— 所以必须写 `liveBuffers`。
2. **system 会被提升**：`toLlmMessages()` 收尾是 `capped.filter { it.role == "system" } + kept`
   （`QuroConversation.kt:298`），system 提醒会被搬到上下文最前，与系统提示混在一起，模型容易当背景噪声。
   因此注入使用 `role=user` + `hidden=true`（`hidden` 语义：用户看不见、LLM 看得见）。
3. **时序**：`baseMessages` 在 ReAct 的 `while` 内每轮重建（`QuroAssistant.kt:436/468`），
   但一次模型请求一旦发出就无法回改；注入只能影响**下一次**请求。

## 四、三种落点对比

| 方案 | 效果 | 代价 | 现状 |
|---|---|---|---|
| 轮末唤醒（`pendingKick`） | 下一轮必读到 | 延迟 = 本轮剩余时间（长任务可达数分钟） | **已实现并实测成功** |
| barge-in（`send()` 隐藏消息） | 点击即打断并起一轮 | 当前轮被取消 | 已实现，仅在空闲时触发 |
| 宿主循环内注入 | 两者兼得 | 需宿主改造 | 已在 issue #13 提出 |

## 五、复现

```bash
# 1. 构建插件（需 ZorvAI 源码的 plugin-contract 模块）
JAVA_HOME=<jdk17> ./gradlew :plugin-whale:assembleDebug

# 2. 安装（官方发布包与自研插件签名不同，走宿主自带的调试参数）
#    apk_plugin(action="install", path="/sdcard/Download/plugin-whale-debug.apk", skip_signature_check=true)

# 3. 装完必须 reload 两次并等 5 秒（轮询线程首启动偶尔不拉起）

# 4. 造一次点击后读状态
#    whale_bridge_status
```

## 六、已知限制与踩坑

| 项 | 说明 |
|---|---|
| 签名 | 宿主为官方发布签名（`CN=ZorvAI, OU=Release`），自研插件只能走 `skip_signature_check=true` 调试口；仅限本机自用，可 `apk_plugin(action="uninstall")` 回退 |
| reload | 安装后单次 reload 有时轮询线程不启动，**reload 两次 + 等 5 秒** |
| 日志 | 本机 ROM 只保留 E 级日志，`QuroLlmClient` 的请求日志是 `Log.i` → 无法从 logcat 观测请求体 |
| 去重 | 插件按事件 id 持久化去重；测试频繁造事件时会命中旧 id，需造新 id |

## English summary

On ZorvAI v1.1.10 the plugin-driven path is verified end to end: the tap reaches the APK, the plugin
injects into the turn-local buffer (`liveBuffers[convId]`), and the marker survives `toLlmMessages`,
`normalizeToolCallMessages` and `sanitizeForLlm` (measured twice, always present).

The one remaining limit is **timing**: every model request of a turn is built before the injection, so the
reminder can only be read by the *next* turn. Three outcomes are possible — end-of-turn wake (implemented),
barge-in (implemented, idle-only), or true in-loop injection (requires host support, filed in issue #13).
