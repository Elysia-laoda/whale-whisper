# 补充提示挂件（Supplement Widget）

用户点击挂件 → 你会收到「补充提示挂件·事件 <id>」→ 你必须立刻调用 AskUserQuestion 问用户「有什么要补充的吗？」。这样用户不用打断任务，也能把临时想到的提示词塞进来。

## 两种形态（默认用桌面版，别主动打开对话内版）

| 形态 | 说明 | 什么时候用 |
| --- | --- | --- |
| **桌面版小鲸鱼**（默认） | 常驻屏幕右下角、可拖动；点击后由钩子把事件转达给你 | 它的启停由用户双击 `overlay/` 下的 vbs 管理，**与你无关，不要尝试去开关它** |
| **对话内挂件**（工具 `open_supplement_widget`） | 渲染在对话里的卡片 | **仅在用户明确要求**（"把挂件放到对话里 / 对话内挂件 / 在对话里挂一个"）时才调用。不要主动打开 |

> 本插件注册了 hooks（SessionStart / UserPromptSubmit / PostToolUse / Stop）：会话开头会注入挂件上下文；用户点击任意形态的挂件后，事件会通过钩子注入到你这里。

## 收到挂件事件时（关键行为）

当你在**系统提醒**或**用户消息**里看到含「补充提示挂件 · 事件 <id>」的内容时：

1. **立即**调用 AskUserQuestion 工具，向用户提问「有什么要补充的吗？」。
   - 可以基于当前任务上下文附上 1–2 个常见补充方向作为选项（例如"补充输出格式要求""调整范围/重点"），但要保证用户能自由输入。
   - 不要先做完当前任务才提问；在下一个动作里优先提问。
   - 不要打断正在执行的单个工具调用（比如已经启动的命令让它跑完），工具一结束就提问。
2. **按事件 id 去重**：同一个事件 id 只需提问一次。如果你已经通过系统提醒或用户消息任一渠道提问过，忽略重复提醒，不要重复问。
3. 用户回答后的处理：
   - 用户给出补充内容 → 用一句话简述你会如何把它纳入当前计划（哪些步骤、哪些产出会调整），然后继续执行。
   - 用户说「没有 / 继续 / 不用了」→ 直接继续原计划，不要追问。
4. 用户如果回答的是全新的需求 → 按新需求正常处理；不要机械地套回原任务。

## 其他用户意图

- 用户说「**关掉挂件 / 不用挂件了**」→ 钩子会自动让本会话闭嘴；如果用户是要退出桌面挂件，告诉他双击 `overlay/stop-overlay.vbs`（或右键挂件菜单→退出）。
- 用户说「**挂件开机自启**」→ 告诉他双击 `overlay/enable-autostart.vbs`；取消用 `disable-autostart.vbs`。
- 用户抱怨「挂件不在 / 挂了」→ 让他双击 `overlay/start-overlay.vbs` 重新启动。

## 不要做的事

- 不要主动打开对话内挂件刷屏；用户没要求就不开。
- 不要把「挂件事件」当成任务取消信号：它的语义只是"用户想补充提示"。
- 钩子注入的提醒里已经写清楚可忽略的条件（简单问答、已处理过同一事件、用户表示不需要）——符合条件时直接忽略，不要向用户提起"提醒"本身。
